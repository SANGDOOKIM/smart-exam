# Claude Code 단계별 지시문 (11주차)

VS Code의 Claude Code 대화창에 아래 단계를 하나씩 붙여 넣어 진행합니다. 각 단계의 결과를 확인한 뒤 다음 단계로 넘어갑니다.


## 준비

- 바탕화면 등에 smart-exam폴더를 만들고 VS Code에서 엽니다.
- PDF 2개를 폴더에 넣고 이름을 gemini.pdf(100문제), claude.pdf(120문제)로 바꿉니다.
- Claude Code를 열고 1단계부터 시작합니다.

## 1단계: 전체 작업 이해시키기

```text
스마트공장 수준확인 심사원 시험 대비용 모의고사 웹앱을 만들 거야.
PC와 스마트폰 브라우저에서 모두 사용할 거고, 시험이 얼마 남지 않아서 단순하고 실용적으로 만드는 게 가장 중요해.
[기술 조건]
- 순수 HTML, CSS, JavaScript만 사용 (프레임워크, 빌드 도구, 서버, DB 없음)
- 파일 구성: index.html, style.css, app.js, questions.js
- questions.js는 window.QUESTIONS = [...] 형식으로 만들어 index.html을 더블클릭해도 동작하게 해 줘
- 시험 기록은 localStorage에 저장
- 화면 문구는 모두 한글
지금은 코드를 작성하지 말고, 위 4개 파일의 역할을 짧게 설명한 뒤 내 다음 지시를 기다려 줘.
요청하지 않은 기능은 앞으로도 추가하지 마.
```

## 2단계: PDF를 문제 데이터로 변환

```text
gemini.pdf와 claude.pdf를 읽어서 220문제 전체를 questions.js로 만들어 줘.
[구성]
- gemini.pdf: 객관식 100문제, 뒤쪽 정답표 사용, 해설 없음
- claude.pdf: 객관식 100문제 + 단답형 20문제, 뒤쪽 정답·해설 사용
[데이터 형식]
객관식:
{ "id":"G-001", "type":"choice", "question":"문제", "options":["보기1","보기2","보기3","보기4"], "answer":2, "explanation":"" }
단답형:
{ "id":"S-001", "type":"short", "question":"문제", "answer":"3년", "accepted":["3년","3"], "explanation":"" }
[규칙]
- id: gemini 객관식은 G-001~G-100, claude 객관식은 C-001~C-100, claude 단답형은 S-001~S-020
- answer는 객관식 정답 번호 1~4 (①=1)
- 문제 문장이나 보기가 줄바꿈으로 끊긴 곳은 자연스럽게 이어 붙여 줘
- 한 줄에 붙어 있는 ①②③④ 보기는 4개로 분리해 줘
- 머리글, 페이지 번호, 영역 제목, 안내문, 응원 문구는 문제에 포함하지 마
- 문제와 보기의 내용은 임의로 고치거나 요약하지 마
- claude.pdf의 해설은 explanation에 넣어 줘. 해설 끝의 근거 표시(규정, 공고, 표준, 일반)는 빼 줘
- accepted에는 같은 뜻의 답을 넣어 줘
  예: "5명(5인)" → "5명", "5인", "5"
  예: "1,000점" → "1,000점", "1000점", "1000"
  예: "AI(인공지능) 기능" → "AI", "인공지능", "AI 기능", "인공지능 기능"
완료 후 변환된 문제 수를 알려 줘.
```

## 3단계: 데이터 검증

```text
questions.js를 검증하는 일회용 스크립트를 PC에 설치된 도구로 실행해서 아래 항목을 확인해 줘.
1. 전체 220문제, 객관식 200문제, 단답형 20문제인지
2. id 중복과 누락이 없는지
3. 모든 객관식의 보기가 정확히 4개이고 빈 값이 없는지
4. 모든 객관식의 answer가 1~4인지
5. 모든 단답형에 answer와 accepted가 있는지
6. 정답을 PDF의 정답표와 전부 다시 대조했을 때 불일치가 없는지
7. 문제나 보기에 "Page", "예상문제집", "[제1영역]" 같은 잔여 문구가 없는지
문제가 있으면 questions.js를 고친 뒤 다시 검증해 줘.
마지막으로 G-008, G-051, C-072, S-020의 내용을 보여 줘. 내가 PDF와 직접 비교할게.
```

## 4단계: 문제 화면과 기능 1~3

```text
index.html, style.css, app.js를 만들어 줘.
[기능01] 앱을 열면 시작 화면과 [모의고사 시작] 버튼을 보여 주고, 시작하면 220문제에서 중복 없이 25문제를 무작위로 뽑아 줘.
[기능02] 한 화면에 한 문제만 보여 줘.
- 객관식: 라디오 버튼 4개. 보기 글자를 눌러도 선택되게 해 줘
- 단답형: 텍스트 입력칸
[기능03] 화면 구성
- 상단 바 왼쪽: 현재 문제 번호 (예: 3 / 25)
- 상단 바 오른쪽: [답 확인] [Next] [모의종료] 버튼
- 상단 바 아래 남은 화면에서 위쪽 2/3는 문제 영역, 아래쪽 1/3은 답 확인 영역
- 내용이 길면 각 영역 안에서 스크롤되게 해 줘
- [답 확인]을 누르면 답 확인 영역에 정답을 보여 주고, 해설이 있으면 함께 보여 줘
- [Next]를 누르면 다음 문제로 이동하고 답 확인 영역을 비워 줘
[UI]
- 일반적인 웹 서비스처럼 흰 배경의 깔끔한 스타일
- 스마트폰 화면(폭 360px)에서도 버튼 3개가 잘리지 않고 손가락으로 누르기 쉽게
- 높이는 모바일 주소창을 고려해 100dvh 사용
[모의종료] 버튼은 이번 단계에서는 자리만 만들어 줘.
```
> 확인할 점:index.html을 더블클릭해 25번까지 넘어가는지, 답 확인이 나오는지 봅니다.

## 5단계: 미응답 알림과 채점(기능 4~5)

```text
app.js와 필요한 화면을 수정해서 아래 기능을 추가해 줘.
모든 알림은 브라우저 기본 alert가 아니라 화면 가운데 뜨는 알림창으로 만들어 줘.
[기능04] 답을 선택하거나 입력하지 않고 [Next]를 누르면
"답을 하지 않으면 모의고사가 진행되지 않아요" 알림과 [확인] 버튼을 보여 주고, 다음 문제로 넘어가지 않게 해 줘. 공백만 입력한 경우도 미응답으로 처리해 줘.
[기능05] 25번째 문제에서 답을 하고 [Next]를 누르면 25문제를 채점해 줘.
- 알림창에 "25문제 중 OO문제 정답"과 결과를 표시
- 18문제 이상이면 pass, 18문제 미만이면 fail
- [확인]을 누르면 알림창이 닫히게 해 줘
[단답형 채점]
공백을 제거하고 영문 대소문자를 구분하지 않으며, accepted 중 하나와 같으면 정답으로 처리해 줘.
[채점 검증]
정답 수가 17개, 18개인 경우를 코드로 시험해서 fail, pass가 맞게 나오는지 확인해 줘.
```

## 6단계: 모의종료와 기록 리스트(기능 6)

```text
아래 기능을 추가해 줘.
[기록 저장]
- 기능05의 채점이 끝나는 순간 localStorage에 한 번만 저장
- 저장 항목: 날짜(시스템 날짜 YYYY-MM-DD), 회차, 맞춘 개수, pass 여부
- 회차는 저장된 기록 수 + 1
[기능06: 모의종료 버튼]
- 25문제를 끝낸 뒤 누르면: 추가 저장 없이 기록 리스트로 이동
- 푸는 도중 누르면: "지금 종료하면 안 푼 문제는 오답으로 기록됩니다" 알림과 [확인] [취소]를 보여 줘
- 푸는 도중 [확인]을 누르면: 지금까지의 답을 채점해 저장하고 기록 리스트로 이동
[기록 리스트 화면]
- 표 형식: 날짜 / 회차 / 맞춘 개수(예: 20/25) / pass 여부
- 최신 기록을 위에 표시
- 아래에 [새 모의고사 시작] 버튼
시작 화면에도 [기록 보기] 버튼을 넣어 줘.
```

## 7단계: 최종 점검과 스마트폰 배포

```text
앱 전체를 점검해 줘.
1. 기능01~06이 요구대로 동작하는지 코드 기준으로 확인
2. 25문제에 중복이 없는지, 긴 문제와 보기가 폭 360px 화면에서 잘리지 않는지 확인
3. 발견한 오류 수정
4. 배포에 필요한 index.html, style.css, app.js, questions.js만 deploy 폴더에 복사
그다음 Netlify Drop으로 deploy 폴더를 올려 스마트폰에서 접속하는 방법을 초보자 기준으로 단계별로 설명해 줘.
```
> 배포 후 받은 주소를 스마트폰 홈 화면에 추가하면 지하철에서도 바로 열 수 있습니다. 기록은 기기별로 저장되므로 PC와 스마트폰의 기록은 합쳐지지 않습니다.
